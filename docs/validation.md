# OCV 검증 기록

## 원본과 중복 저장소

기존 ocv__의 app.py, ocv_model.pkl, README 및 Git 이력은 mirror로 보존했다. 원격 main은 변경하지 않았다. ml_streamlit도 같은 데이터 업로드·분류 문제를 다루므로 별도 battery 저장소를 즉시 만들지 않고 ocv__에서 검토한다. 기존 앱 소스는 부모 커밋 7407e2aa9e99d4d550b9ddf770248c7463e812f3에서 확인할 수 있다. 과거 README가 요구하던 train_model.py가 없었으나 이번 브랜치에서는 재현 CLI를 제공한다. 과거 모델 pickle을 이번 실험의 검증된 모델이라고 표시하지 않는다.

강의용 노트북의 빈칸은 교육 의도이며 프로그램 결함으로 간주하지 않는다. 제공 파일명과 노트북의 옛 입력 경로는 다르다. 노트북 설명의 불량률 약 1.8%는 제공 샘플의 실제 8.47%와 맞지 않는다. 자료를 외부 제공 예제로 단정하지 않고 사용자 본인이 진행한 내부 교육 자료로 구분한다. 파일별·팀별 원래 작성 기여를 추가 추정하지 않는다.

## 데이터와 누수

강의용 Excel 12,000행에 OCV1~4, 생산일자, 제품명, OK_NG가 있다. NG=1,016, OK=10,984, 전체 결측 0, 측정값+정답 중복 0이다. 9개 생산일과 1개 제품이 있으며 셀 고유 ID는 없다. OCV4<35와 OK_NG가 모든 행에서 일치한다.

- 사전 예측 입력은 OCV1~3뿐이다. OCV4·정답·생산일·제품명은 feature builder가 사용하지 않는다.
- OCV4 사용은 최종 측정 후의 판정·진단일 수 있으나 사전 예측으로 표시할 수 없다.
- 과거 앱의 80/20 무작위 분할·GradientBoosting 설정을 같은 샘플에서 재실행했다. OCV1~3의 Precision 0.3170/Recall 0.6700, OCV1~4의 Precision/Recall 1.0이었다. 이전 모델 pickle의 결과를 재현한 것이 아니라 현재 앱의 학습 로직을 실행한 결과다.
- 강의 샘플의 생성·익명화 방법과 실제 제조 원자료와의 동일성은 확인되지 않았다. 제공 샘플 결과는 고객사 양산 성능으로 표현하지 않는다.

## 분할과 모델 선택

생산일 순서로 5일(7,200행, NG606)/2일(2,880행, NG250)/2일(1,920행, NG160)을 분리했다. 결측 대체와 표준화는 Pipeline 내부에서 학습 자료로 fit한다. 클래스 가중치도 학습 빈도만 사용한다. 그룹 식별자가 주어지면 분할 간 교차를 거부한다. 그룹 단독 분할을 별도로 지원한다. 현재 파일에는 셀 ID가 없으므로 생산일 분리만으로 반복 셀 누수를 완전히 검증했다고 주장하지 않는다.

시드42, 모델별 사전 고정 설정, 검증셋 AP로 모델 선택, 검증셋 F1의 사전 그리드(0.05~0.95)로 임곗값을 선택했다. RF가 검증 AP로 선택됐다. 평가셋에서 XGBoost AP가 더 높아도 선택을 변경하지 않았다. 하이퍼파라미터 탐색을 반복하여 특정 성과 수치에 맞추지 않았다.

무작위 분할도 동일 코드로 60/20/20 분리했다. 기존 앱 80/20과는 학습량·분할·모델이 다르므로 전후 숫자의 차이를 누수 제거 하나의 효과로 해석하지 않는다. 임곗값 전후 비교는 같은 RF와 같은 생산일 평가셋에서 수행했다.

AP는 average precision이며 사다리꼴 PR-AUC와 별도로 JSON에 저장했다. 높은 accuracy만으로 소수 불량 검출을 평가하지 않는다. 분류 점수는 가중 학습의 출력이며 보정된 불량 확률로 제시하지 않는다.

## 오류 사례

선택 RF는 평가 NG160개 중 80개를 놓쳤고 정상 1,760개 중 35개를 NG로 판단했다. 미검출 80개는 모두 OCV3>=35에서 OCV4<35로 최종 기준선을 넘었다. 하지만 전체 NG160개도 모두 같은 조건이므로 이것만으로 FN과 TP를 구분하거나 ‘특정 25%는 원천적으로 예측 불가능’하다고 결론 낼 수 없다. 낮은 회귀 R² 역시 정보 부재나 불가능성의 증명이 아니다.

개별 오류 행과 원본 측정값은 private 디렉터리에 보존하고 게시하지 않는다. 추가 센서·측정 시점·온도·로트·공정 조건을 확보한 뒤 사용 가능 시점과 누수를 검토해야 한다. 이번 실험에서는 근거 없이 추가 모델·가상 측정값을 도입하지 않았다.

## 6σ/5σ와 분류 지표

Recall=TP/(TP+FN)은 실제 불량 중 검출률이고, Precision=TP/(TP+FP)은 불량 판정 중 실제 불량 비율이다. 공정 시그마 수준은 규격·기회 수·단측/양측·장기 이동 가정 등 다른 정의를 갖는다. 이 지표를 서로 같은 수치로 바꾸면 안 된다.

일반적으로 인용하는 6σ 약3.4DPMO, 5σ 약233DPMO는 1.5σ 장기 이동 관례를 전제한다. 이동을 두지 않은 정규분포 꼬리확률과도 다르다. 고객 기준이 셀당 출하 불량인지, 검사 기회당 결함인지, 정상 셀 과검인지 먼저 확인해야 한다.

불량 유병률을 π라고 하면 전체 셀당 불량 유출률은 π×(1−Recall), 전체 셀당 정상 과검률은 (1−π)×FPR이다. Precision은 유병률에도 의존한다. 이번 평가의 FN/전체=80/1920과 FN/실제NG=80/160은 각각 다른 분모다.

불량 유출 0건을 관측해도 95% 단측 상한은 약3/n이다. 3.4ppm 이하를 0건 관측으로 주장하려면 단순 독립 베르누이 가정에서도 약88만 건 이상의 대표성 있는 기회가 필요하다. 12,000행의 교육 샘플과 몇 개 생산일로 양산 6σ를 검증할 수 없다. 이번 분류 모델을 고객 요구 수준 달성으로 표시하지 않는다.

## 포트폴리오와 면접

검증된 내용은 ‘OCV4 유입을 배제한 사전 예측 평가, 생산일·검증셋 분리, 4모델 및 임곗값 trade-off 비교’다. Recall0.98/Precision0.94는 원래 제조 자료·당시 코드·분할·임곗값이 없고 이 실행에서도 재현되지 않아 검증된 성과에서 제외한다.

본인 역할은 이력서와 사용자 확인 기준 ML 모델링·파생변수 설계·판독 도구·교육 자료 준비 및 강의로 기록한다. 이번 재현 코드·검증 변경과 원래 개발 이력을 구분한다. 면접에서는 OCV4가 왜 사전 예측 누수인지, F1 최적점이 왜 공정 최적점이 아닌지, 검증 AP로 선택한 RF를 평가 결과 때문에 바꾸지 않은 이유, σ 수준과 Recall 분모 차이를 설명한다.
